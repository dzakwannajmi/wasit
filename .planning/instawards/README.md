# Instawards planning

Tracks Wasit's progress against the Instaward SOW — deliverables, evidence,
and outreach traction — separately from the root `README.md`. The root
README is written for a developer deciding whether to use Wasit; this folder
is written for the Chapter Lead / SCF reviewer checking the SOW against what
was actually built. Mixing the two would force one document to serve two
different readers.

**Start at `STATUS.md`.** It's the single source of truth: key facts, the
SOW's own deliverables, a job board (one file per remaining piece of work,
numbered `00`–`04`), open decisions, and a session log. Each numbered file
has its own goal, acceptance criteria, and a `Result` section filled in once
the job is done — update the job file and `STATUS.md`'s table together,
don't let them drift apart.

Layout modeled on a reference `.planning/instawards/` structure the builder
pointed to (cryptoeights/orbit-protocol), adapted to Wasit's own SOW and
status.

Nothing here is meant to be polished prose. It's a working checklist, updated
in place, so status can be trusted at a glance.
